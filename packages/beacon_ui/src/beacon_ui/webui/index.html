API / CLI cheatsheet

Settings

Configuration, not measurement — nothing here answers a question about how a system is doing, so none of it is in the navigation.

Team

Everything in beacon belongs to exactly one team — benchmarks, runs, results, and the people allowed to see them. Members see their team's data and nothing else; switching team switches the whole workspace. It is the access boundary, not a folder.

A new team is a new sealed world — for a second organization whose data yours must not see. A new system under test is not a team: it declares itself when its runner registers a run, and lands in this team's Results. Teams have no delete endpoint at all — removal means removing the members.

Access

Who can see this team's data, and what they may do: a team_member registers runs and pushes results; a team_admin also manages benchmarks, members and the reference pin. Adding an email that has no account yet creates it — then issue key on their row and hand the key over; it is how an invited person signs in for the first time.

Your API keys

A key authenticates you — paste it at the sign-in screen, or set BEACON_API_KEY for a runner pushing results as you. Shown once; stored as a hash. To give a teammate their first key, use issue key on their row in Access above.
